# Adaptive Concurrency 合成負載

十二份文件分成 A、B、C、D 四組，各三份。`next` 指向同組下一份，最後為 `END`；`marker` 用於比對讀取結果歸屬。資料全部為合成驗收資料。

| 組別 | 預期 value 加總 |
| --- | --- |
| A | 36 |
| B | 66 |
| C | 96 |
| D | 126 |
| 全體 | 324 |

在這個工作區使用 Ask 模式，同時分派四個 explore 子任務；各自從對應的 `load/X-1.md` 開始，依實際工具結果的 next 逐步 read_file。每個子任務回報 marker 與加總，主 Agent 收集整合。每一步須依上一份結果決定，不使用批次讀取。

正常規劃約需十九個主／子模型請求；額外的格式修正回合仍受原任務模型預算與請求節奏限制。保留預設每 61 秒窗口八次與 240 秒回應逾時。觀察名額、Agent、模型請求及 Queue；不透過切換 Profile、增加請求速率或重送失敗請求促使驗收成功。若有 429、登入失效或服務限制，停止驗收。

成功只代表當次環境。完整執行結果見專案根目錄 `VALIDATION.md`。
