# Agent 設定檔

設定檔以同目錄暫存檔及原子發佈保存，寫入失敗會保留舊檔；首次建立需要檔案系統支援 hardlink。若專案位於不支援此功能的 FAT／exFAT 或部分網路磁碟，建立會明確失敗，可改用一般本機磁碟的設定檔。

聊天頁面上的 Agent 模式、分析深度、核准模式、網路搜尋與預載 Skills，可以保存為 JSON 設定檔，供同一專案或其他聊天重複使用。

## 建立與套用

1. 在 NTPU AI 的「工具」頁按「編輯專案設定檔」。擴充功能會在目前選定的專案根目錄建立 `.ntpu-ai.json`，內容取自目前聊天；檔案已存在時直接開啟，保留既有內容。
2. 編輯 JSON 並儲存。VS Code 會使用套件內附的 JSON Schema 提供選項提示及格式檢查；檔名可用 `.ntpu-ai.json` 或 `任意名稱.ntpu-ai.json`。
3. 按「套用設定檔」，選擇已儲存的檔案。核准區會列出套用後的選項；按「套用設定」才會更新目前聊天。

「匯出目前設定」可另存一份完整設定檔，供其他專案使用。也可以從命令選擇區執行：

- `NTPU AI: 編輯專案 Agent 設定檔`
- `NTPU AI: 套用 Agent 設定檔`
- `NTPU AI: 匯出目前 Agent 設定`

```json
{
  "schemaVersion": 1,
  "agent": "build",
  "depth": "deep",
  "permission": "assisted",
  "web": true,
  "skills": []
}
```

## 支援的選項

| 欄位 | 可用值 | 效果 |
| --- | --- | --- |
| `schemaVersion` | `1` | 必填的設定格式版本。 |
| `agent` | `build`、`plan`、`review`、`research`、`ask` | 對應 Build／Plan／Review／Research／Ask。Build 可實作；其他模式保留既有唯讀限制。 |
| `depth` | `quick`、`standard`、`deep` | 對應快速／標準／深入，調整任務策略與可用步數上限，仍受擴充功能的總步數設定約束。這不會設定校方模型的原生 thinking 參數。 |
| `permission` | `ask`、`assisted`、`full` | 對應要求核准／協助核准／完整存取，沿用聊天頁面既有權限規則。 |
| `web` | `true`、`false` | 是否允許公開網路搜尋與網頁讀取。 |
| `skills` | 最多四個已安裝 Skill 的名稱 | 例如 `["review"]`；名稱須與目前掃描到的 Skill 相符，`[]` 可清除預載項目。 |

除了 `schemaVersion`，至少需指定一個選項。沒有列出的選項會保留目前聊天的值，例如以下檔案只改變分析深度：

```json
{ "schemaVersion": 1, "depth": "deep" }
```

設定檔使用 UTF-8，大小上限為 16 KB；JSON 不支援註解。未知欄位、錯誤值或尚未安裝的 Skill 會被拒絕，避免只套用部分錯誤設定。

## 套用範圍與核准

檔案在使用者選擇、預覽並核准後，才會套用至目前聊天。建立、編輯、儲存或開啟專案本身不會自動套用；新聊天也不會自動繼承檔案。需要時可在新聊天再次套用。

切換為 `full` 會在同一次核准中顯示完整存取說明，按鈕為「啟用完整存取並套用」。檔案無法取代敏感資料確認、Shell／MCP 沙箱與主機安全限制。套用後會清除目前聊天先前暫時授予的工具權限，重新依所選核准模式判斷。

從 0.6.13 起，畫面上選擇或經確認套用的核准模式會立即存盤，同一聊天重啟／重新載入後會保留，不再一律重設為 `ask`。首次啟用 `full` 仍需原有確認；只修改設定檔不會自動啟用。這項保存適用於更新後選定的模式，舊版尚未確認保存的值維持 `ask`。

新聊天和從備份還原而建立的聊天，仍從 `ask` 開始；個別工具的臨時核准不會隨重啟恢復。畫面選項保存在聊天；如要更新一份既有 JSON 檔案，請使用「匯出目前設定」，建立或編輯專案檔不會覆蓋它的原有內容。

請先完成正在執行的任務、核准或檔案變更，再操作設定檔。選檔期間若切換聊天或修改選項，套用會停止，避免將舊預覽套到另一筆聊天。取消核准、格式錯誤或儲存失敗都會保留先前選項。

設定檔只包含上述五項聊天選項。瀏覽器登入、專用 Profile、Cookie／Token、MCP 憑證、聊天內容、Task Checkpoint 與 Project Memory 均不會匯出，也不會被匯入設定覆寫。請使用目前已信任的工作區；本機檔案操作會在 Extension Host 所在的電腦進行。
