# 工具自動探索與按需載入

從 0.6.17 起，Agent 可按任務選擇、搜尋並載入目前主機提供的工具，不再只把工具目錄的前 40 個傳給模型。0.6.20 加入官方 MCP Registry 的按需擴充；Plugin 與 computer use 另見[功能說明](PLUGIN_COMPUTER_USE.md)。

## 一般使用

直接描述工作即可，例如「用已連接的文件工具讀取 PDF，整理結果並保留來源」。不需要手動指定工具名稱。

- 任務開始時，本機依提問關鍵字，自動載入最多三個相關、規格較小的已連線 MCP 工具。這是本機文字比對，不是額外的模型請求，也不會執行工具。
- 缺少所需能力時，Agent 使用 `search_tools` 搜尋全部可用工具與已設定 MCP。可使用中文、英文及工具原名；找不到時可換短關鍵字或翻譯後再查。這不是全網工具市集搜尋。
- Agent 使用 `describe_tool` 取得選定 MCP 工具的完整 JSON Schema，再依規格呼叫。大規格每頁最多 2,000 字元，依 `nextOffset` 與 `version` 接續；規格尚未完整取得時不開放新工具。
- 已設定但未連線的 MCP 會顯示可連線狀態。具備連線權限的主 Agent 可使用既有 `connect_mcp` 提出核准，取得連線後再搜尋、載入。不會自動安裝程式、匯入其他 Agent 的設定或讀取憑證。
- MCP 增減工具時，Agent 可使用 `search_tools` 並指定 `server`、`refresh:true`，重新取得該已連線伺服器的全部工具頁。連線、逾時、取消或分頁異常不會套用半份目錄。

輸入框的「Skills／工具設定」仍可管理 MCP 與 Skills。執行紀錄會顯示「探索可用工具」、「載入工具規格」及後續真實工具結果。

## 缺少工具時自動擴充（0.6.20）

直接描述要完成的工作，例如「找能處理 PDF 的工具並接續這項工作」。build Agent 先搜尋既有工具；`search_tools` 的結果為零且允許擴充時，會以同一能力關鍵字進入官方 MCP Registry 搜尋。也可主動使用 `discover_mcp`。沒有做過工具探索就回報缺少能力時，主機會要求先查證；連續未查證會以未完成停止，不假裝搜尋過，也不反覆輸出結語。

1. `discover_mcp({"query":"pdf"})`：向固定官方 Registry 查詢最多 80 字的能力關鍵字，只搜尋名稱片段，不是全網語意搜尋。不傳送聊天、檔案、Project Memory 或憑證；可依回傳 `nextCursor` 接續。同一查詢快取有效十分鐘，失敗不自動重送。
2. 檢視候選的來源、名稱、版本、原始碼網址、建議 endpoint 與需求。Registry 收錄只表示有該筆發布資料，**不是安全背書**。描述與套件資料都是不可信任的 metadata。
3. `expand_mcp({"id":"回傳的候選 id"})`：主機重新取得該固定版本，確認候選未變更／過期及 DNS 全為公開位址，再要求使用者核准。Agent 不能傳入另一個 URL 或命令取代候選；即使完整存取也必須確認新連線。
4. 核准後做真正的 MCP 握手及完整 `tools/list`，有有效工具才保存公開連線設定與來源。只開啟 URL、下載資料或沒有拋錯，都不能算完成。失敗／取消會清理自己的連線；保存失敗會回復原設定，若儲存服務連回復都失敗會明確提示人工處理。
5. Agent 接著用 `describe_tool` 取得相關工具完整 schema，執行原任務需要的呼叫並檢查真實結果，再繼續工作。新外部工具仍依既有權限逐次核准，不繼承白名單或唯讀地位；不為了測試而任意呼叫具有副作用的工具。

`get_capabilities` 的 `capabilityExpansion.states` 區分 `protocol-and-tools-list`、成功的 `tool-call` 與 `tool-call-failed`；握手成功時 `toolTested:false`、`verified:false`，後續呼叫失敗也不保留成功驗證狀態。這些是本任務的實際驗證紀錄，不代表供應商永遠在線。

### 需要金鑰或本機套件

metadata 列出 headers／金鑰、樣板 URL，或只有 npm／PyPI／OCI 等套件時，會回傳 `requiresConfiguration:true`、`ready:false` 並列出已知需求。**本版不自動安裝或執行 Registry 提供的套件／命令，也不從其他 Agent 設定取得憑證。** 原有 OS 沙箱仍禁止網路，Windows stdio 後端仍未啟用；不會為了讓套件啟動而切換成一般主機程序。

有其他獨立工作可先完成。需要設定時，先結束或停止目前任務，再從「設定 → 工具 → 新增 MCP」處理；金鑰放入 SecretStorage，不貼到聊天。設定好後可在原聊天室要求繼續，Agent 重新搜尋並依既有 `connect_mcp` 核准流程使用。供應商需要但未在 metadata 宣告的驗證，在握手遇 401／403 時也會明確回報設定需求，不重試登入。

### 限制與停止條件

- 關閉網路開關後，不會進行外部目錄探索或擴充；原本已設定 MCP 依既有權限管理。
- 唯讀子 Agent 不新增或連接 server，空搜尋也不暗中送出外部 Registry 請求；由主 Agent 處理擴充。唯讀主模式可以做獲准的 metadata 查詢，不能連線擴充。
- 候選十分鐘過期；版本、endpoint、需求或來源變動要重新搜尋審查。單一任務最多八次 metadata 請求、六十個候選；精確最新版本查詢及連線前重查也計入，不是模型輪數或既有工具總數上限。
- 目錄每次最多二十秒、1.5 MiB，不跟隨重新導向；搜尋／連線的 429 或服務限制會停止擴充，不換名稱重試。新連線拒絕、取消或失敗的候選在本任務不重複詢問。
- 逾時／離線與「搜尋成功但沒有結果」有不同回報；有 `nextCursor` 時不能把當頁零筆解讀成整個目錄沒有能力。沒有把第三方描述或自稱唯讀當成權限證據。

## 工具數量與脈絡

全部目錄可分頁搜尋，每頁最多 20 筆；**沒有前 40 個的可見性截斷**。模型同時保留最近六個 MCP 工具，這是提示內的快取大小，不是整個任務只能使用六種工具。載入其他工具會回報移出的名稱，需要時可重新載入。

核心檔案、Shell、搜尋、Skills 與探索工具仍直接可用。MCP 規格會依提示字元預算適量帶入，過大規格保留分頁讀取入口；內建工具沿用原本描述與範例，不假稱額外提供不存在的 JSON Schema。既有上下文整理、模型輪數、長文保存與取消機制仍適用。

## 權限與安全

探索／載入不代表核准執行。後續呼叫仍經既有權限、工作區信任、外部傳送與敏感資料檢查。MCP 的名稱、工具描述和 schema 是不可信任的資料，不能擴大權限。

唯讀子 Agent 保留原有工具白名單：即使父任務已載入其他工具，子任務也不能藉搜尋或描述取得寫入、Shell、任意外部工具或再次分派能力。各子任務獨立載入，沒有改動父任務的目錄範圍。關閉網路開關時，Exa 相關工具也不會出現在探索或目錄更新中。

工具中斷連線、被移除或規格變更後，舊載入狀態失效，必須重新探索／讀取；不會靠猜測舊參數繼續執行。配置的 URL、headers、環境變數和 SecretStorage 參照不會被探索結果帶給模型。

單一 MCP 的工具清單採 60 秒總逾時，每頁請求最多 20 秒，最多 100 頁、10,000 個工具、8 MiB metadata；超過會明確失敗，不會把不完整清單當成完整成功。沒有自動重試失敗連線，也沒有放寬既有沙箱或校方限制。

## 驗證

單元／整合測試涵蓋 240 個工具的搜尋分頁、完整大 schema 接續、規格變更／移除、載入快取、最低提示預算、核准拒絕、秘密遮蔽、網路關閉、唯讀子任務範圍、取消及原子目錄更新。真正的 localhost stdio MCP fixture 提供 75 個分頁工具，WorkspaceTools 能搜尋、載入並呼叫第 65 個工具；受控模型回覆亦驗證主 Agent 的完整工具循環。

這些測試不使用學校帳號、不呼叫真人 NTPU 模型，不代表所有第三方 MCP、認證方式或模型都已實測。

0.6.20 新增官方目錄分頁／來源重查、真實 MCP HTTP 握手與兩頁工具目錄、主 Agent 從缺能力到實際呼叫並接續原任務，以及取消／儲存回復／401／429／最低脈絡預算回歸。最新版本標記與單一 server 的最新版本查詢避免了實測中名稱搜尋加 `version=latest` 的慢查詢；精確 API 定義見 [MCP Registry 官方規格](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/openapi.yaml)。
