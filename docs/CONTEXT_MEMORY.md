# 聊天記憶與輸入預算

同一個聊天室保有完整本機對話與任務紀錄。模型每次能收到的內容則有大小限制；本機保存與當次帶入是兩件事。

## 同一聊天室如何延續

每次請求由本機重新組裝當前需求、主機規則、近期聊天、任務工具證據、相關較早歷史與 Project Memory。近期對話與最新工具證據優先使用可用空間；較早內容依關鍵字、中文片語、檔案及未完成狀態挑選。沒有固定「只帶最近八則、每則前 1,600 字」的限制；在預算內可保留完整訊息，長內容則明確節錄或省略。

模型每次請求使用新的校方對話，並接收本機選出的歷史。這可避免在同一校方對話逐輪附加整份提示詞、讓重複文字持續占用模型上下文。它不會清除本機聊天室；重新載入、接續任務仍從本機保存的 Session 與 Checkpoint 恢復。校方臨時對話仍遵循原有任務保存後清理設定。

記憶是供模型參考的歷史證據，不能證明磁碟上的檔案仍未改變。執行實作與驗證時仍要重新讀取檔案、執行必要檢查。停用 Project Memory 不會停用本機聊天保存。

## 回讀被整理的原文

Agent 的 `search_history` 會搜尋目前聊天室完整的使用者／助理訊息，回傳真實 `messageId` 與命中位置附近的節錄。`read_history` 使用該 ID 分頁回讀，預設每頁 4,000 字元、最多 10,000 字元；若 `nextOffset` 非空，使用回傳值接續下一頁，不能猜測其他聊天室的 ID 或讀取內部工具紀錄。

```json
{ "name": "search_history", "args": { "query": "先前的部署限制", "limit": 5 } }
```

取得實際訊息 ID 後：

```json
{ "name": "read_history", "args": { "messageId": "搜尋回傳的真實訊息ID", "offset": 0, "limit": 4000 } }
```

整則訊息先通過憑證遮蔽，再搜尋與切頁。`offset`、`totalCharacters` 與 `nextOffset` 都針對遮蔽後文字，可能與本機原始文字長度不同；不能改用原始位置拼接繞過遮蔽。中斷／未完成的訊息仍帶有狀態標記，不能當成已完成結果。

## 「本輪輸入」代表什麼

`ntpuAI.contextCharacters` 是擴充套件對單次輸入設定的本機字元預算，預設 64,000 字元。它不是 Token 數，也不是校方宣告的模型上下文長度。不同文字與模型的 Token 換算不同；本專案透過網站操作，無法準確量測模型內部的原生上下文使用率。

- **本輪輸入 75%**：本次組裝文字使用本機字元預算的四分之三。
- **已整理**：為符合預算，本輪內容經過選取、節錄或省略。
- 提示會列出實際字元數、節錄與未帶入的紀錄數；螢幕閱讀器可讀取相同說明。
- 未達 100% 的數值不會四捨五入成 100%；若實際達到上限會明確說明。

內容超過本機預算約 85% 時，組裝器會自動整理，目標保留約 15% 的組裝空間。必要的主機規則和目前需求仍優先，細小預算下可能超過這個目標，但不應超出硬上限。這個空間是本機文字預算的設計，不能當成校方模型輸出 Token 的保留量。無法在硬上限內安全組裝的需求會回報錯誤，不以無聲切掉必要指令的方式送出。

## 整理不會刪除完整內容

整理只影響本次模型輸入。本機原始訊息、工具結果、修改紀錄、任務與檢查點仍保留，可從聊天與記憶頁檢視或匯出。較早內容可能不會每輪全部送出；節錄與檢索也不保證模型理解每個細節。對特定條文、程式碼或長文件有完整原文需求時，請明確指出檔案或範圍，讓 Agent 重新讀取。

長回覆的分段保存與這個輸入預算不同：前者保留模型已產生的完整輸出，後者限制下一輪提供模型的文字量。參閱[長內容保存與限制](LONG_OUTPUT.md)。憑證遮蔽、敏感資料確認、核准模式與沙箱規則仍適用，完整保存不會放寬防護。

## 輪數預算

上下文字元預算與任務輪數也分開計算。預設主 Agent 與子 Agent 共用 100 次模型回合；VS Code `settings.json` 中的 `"ntpuAI.maxSteps": 200` 可將上限提高至 200。標準／深入模式使用設定值；快速模式仍最多 12 輪。這個選項不放在 `.ntpu-ai.json`，不會提高本機請求頻率或放寬校方限制。
