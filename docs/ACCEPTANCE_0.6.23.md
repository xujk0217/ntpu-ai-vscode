# 0.6.23 本機驗收

## 變更範圍

- 使用者從附件選擇器選取圖片／PDF 後，直接準備附件，不顯示重複的資料傳送警告。受保護路徑、格式、容量與 OCR 檢查仍執行；未就緒的附件不能送出。
- 聊天頂端、聊天列表選單及記憶頁不再提供整份聊天記錄匯出。主機移除該功能，舊 Webview 的匯出訊息不會開啟儲存對話框；批次管理也不接受 export 操作。
- 本機歷史、改名、封存、多選刪除、任務接續、個別文件另存、圖片另存與記憶備份沿用各自功能。
- README 收斂為主要能力、安裝與工作流程；兩張主畫面截圖由實際 Webview 搭配明確示範資料產生。

## 本機結果

在 macOS arm64 執行：

- 420 項單元／整合回歸通過。完整測試中的本機 MCP／Plugin fixture 需要允許監聽 localhost；受限制執行首次遭 EPERM，授予本機測試所需環境後全數通過。
- 附件案例涵蓋 PNG、JPG／JPEG、WebP、GIF、PDF，不呼叫傳送警告；仍涵蓋超大附件、檔案不存在、掃描失敗、受保護路徑、取消、切換聊天、關閉與更新互鎖。
- 保留非使用者主動選取附件的私人專案資料確認，拒絕仍有效；未擴大 Agent 自動讀取或傳送的權限。
- UI build、Chrome localhost 登入交接／串流／附件／歷史／設定 fixture 通過；更新按鈕緊鄰聊天記錄入口，頁面不再有聊天匯出按鈕，歷史編輯選單也不提供匯出。
- 已檢視 README 首頁與主要聊天截圖，並確認本機文件連結及圖片存在。可執行 `npm run build` 後以 `node scripts/readme-screenshots.js` 重現示範畫面。

## 驗證界線

以上為本機合成資料與 Mock／localhost 測試，沒有讀取使用者的作業 PDF，沒有呼叫真正 NTPU AI，也沒有重新驗收真人 SSO。四平台 CI 與原生 VSIX 以此版 Release 附上的實際執行紀錄為準；Windows Shell／stdio 與原生桌面等既有限制見[平台對照](PLATFORM_PARITY.md)。
