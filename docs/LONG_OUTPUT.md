# 長內容分段與本機保存

長文件採用完整 JSON 分段回覆。模型每次傳回一段原文；主機依固定文件 ID 和連續段號驗證，將原文與下一段的檢查點一起存入本機 Session，再請求下一段。介面會逐步顯示累積內容和已保存段數。各段按原順序直接串接，保留換行與 Markdown，沒有用摘要取代文件。

在主回覆旁按 **另存完整內容**，可輸出 Markdown 或文字檔。展開子任務後可 **查看完整子任務原文** 或 **另存完整子任務原文**。整份聊天記錄的匯出功能已移除，個別文件原文仍可另存。介面的工具證據預覽仍可限長，但完整結果另行保存在 Session，不會再固定截為一萬字。

## 中斷與接續

- 每段的本機保存完成後，下一次模型請求才能開始。段號重複、跳號或文件 ID 改變都不會污染已保存原文。
- 串流中斷會另外保存收到的草稿，標記為未完成。截斷的工具 JSON 只作為未完成資料保存，絕不執行。
- 一般暫時錯誤沿用現有有限恢復流程。已完成段落保持不變；未完成的一段從段首重新產生，避免將不完整 JSON 或半個 Unicode 字元當成完整內容。接續提示要求保留詳情，不做簡化版。
- 取消、登入失效、429 或明確服務限制立即停止自動接續。處理原因後，可透過原有的任務檢查點接續；重啟 VS Code 也保留完整段落和未完成原文。
- 一般單次 `final` 回覆仍相容，也沒有一萬字截斷。若主 Agent 提早回答但子任務尚未收集，暫定答案會另存並標示未完成，等真正結果回來再整合。

## 實際限制

分段是本機工具協定，NTPU AI 模型必須配合回傳。建議每段約兩千字以降低網站單次輸出截斷的風險；這不是校方保證的限制。所有段落共用原任務輪數、請求節奏、取消和服務限制，不能無限自動接續。單份本機分段文件的保護上限為 8 MiB；超出會明確報錯並保留已保存段落，不會靜默裁切。

網站未產生的文字無法由本機復原；模型即使回傳合法完成標記，也仍可能漏寫需求，需要驗收內容完整性。本功能傳送有用的回答、證據與進度，不擷取登入頁、Cookie、Token 或模型未公開的思考內容。既有秘密遮蔽政策仍適用。

修改工作區中的長檔案時，模型應使用小而完整的編輯操作。分段顯示文件不會提高 `write_file` 的檔案大小上限，也不會繞過核准、檔案讀取或沙箱規則。
